# 模型效果与同一现场验收

当前交付优先验证一条主线：**同一现场图片 → AI 候选 → 人工审核 → 道路证据 → 可追溯问答**。三维配准、复杂关系和旧规划分别保留现有能力，未完成主线现场验收前，不以增加模块数量作为完成标准。

不得把这三项的独立通过合并标成一次现场端到端通过。已有数据集保持各自身份；不改名、不平移到同一地图中心、不自动批准真实候选。

## 离线模型评估

examples/evaluate_model.py 只读取人工标定与已保存预测，不请求供应商、不修改业务库、不消耗模型额度。当前没有独立人工真值，随附 manifest 留空，运行应退出 2 并输出 blocked_no_human_gold，所有无分母指标为 null，不是 0% 或 100%。

~~~powershell
.venv/Scripts/python.exe -m examples.evaluate_model docs/validation/model-evaluation-pending.json --output data/model-evaluation.json
~~~

实际评估时复制该文件并填入两个数组。不要把测试夹具、模型自己给出的置信度或另一模型输出当作人工真值。

- images 每项：id、source（原始来源 URL/文件记录）、image_sha256（小写 SHA-256）、human_reviewer（实际审核人）、prediction_run（已保存模型运行记录），以及 gold、predicted 两个数组。每个框包含 label、entity_id、bbox，bbox 用原图归一化的 x_min/y_min/x_max/y_max；predicted 另填 confidence。完整标注图片中的目标，空 gold 只用于人工确认不存在目标的负例。未定位对象的 entity_id 必须来自实际标定的同一对象身份，不编坐标。
- answers 每项：id、question、human_reviewer、prediction_run、should_abstain、did_abstain、allowed_evidence、citations。前者由人工判断该问题有无足够证据，后者从保存回答提取；两组 evidence 值使用后端记录 ID。禁止把未审核或过期证据列为可用证据。
- 保留原始预测、模型名、提示版本和调用时间；不同模型或提示版本分别运行，避免混合统计。先固定留出集，再调提示词；不要挑选成功样本或只标注模型发现的目标。

工具按预测置信度顺序做一次性匹配，默认 IoU ≥ 0.5，类别和对象关联都必须一致；重复框、错对象计误报，未匹配真值计漏检，输出 precision/recall/F1 与逐图计数。另输出应拒答问题的正确拒答率、可回答问题的误拒答率、引用 ID 合法比例和有效引用覆盖率。重复图像散列、重复样本 ID、缺审核人或无效框会被拒绝。

**这些是给定样本的统计，不是上线认证。** 工具不能认证审核人的身份或材料真实性；引用 ID 命中也不能证明回答句子被原文支持，语义正确性仍需逐句人工复核。尚未实现 mAP、类别分层统计或置信区间。至少先收集含正例、负例、遮挡、未知位置、过期证据及不可回答问题的独立样本，再决定覆盖数量和接受门槛，不能从一张照片外推准确率。

## 同场景通过所需证据

验收记录必须能逐项指向原始材料，不能只填写“真实”标签：

1. 同一街区的照片、对象 ID、采集日期/时刻、实测位置和来源；未知项保持未知。照片与道路的关联由审核员核对。
2. 同一区域的道路拓扑、方向、通行方式和有效时间。公开地图只证明拓扑；灾情通行状态另需现场证据。
3. 若验收三维链路，提供同一区域的原始三维材料、坐标系/单位、控制点来源及独立检查点。按目标用途预先规定误差门槛，不能以同一参考变换选点后又声称独立测绘精度。
4. 保存真实调用、审核决定、查询条件、道路结果、句内引用及原图定位；撤回证据后重查应移除相应结论。
5. 用人工真值评估模型与回答，分别报告正确、漏检、误报和信息不足；现场不存在某类材料时，将该分支记作未验收。
