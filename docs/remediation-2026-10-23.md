## 实际代码行为

- 账号库默认 data/access.json.accounts.db；首次迁入旧 JSON 和旧业务库注册申请。迁移按业务库路径记账，重启不会重新导入已处理申请。成员批准的创建账号、移除申请在同一事务完成；两个同时批准请求只允许一个成功。CLI 输入密码时不占用写锁。
- 保留已有工作空间隔离、角色检查、凭据摘要和每请求撤销校验。运行中账号库缺失/损坏会拒绝访问。旧 JSON 已失去权威性，核验升级成功后应安全归档至配置路径之外，避免误删数据库后用旧种子恢复过时凭据。
- 图片仍保持上传原始字节、证据散列与原图框坐标；新增 Pillow 13.0.0。限制文件 5 MB、2000 万像素、单边 10000 像素，并检查文件结构、PNG CRC 和完整解码。没有声称做过恶意文件全类型检测或 EXIF 脱敏。
- 登录不再静态依赖 MapLibre/Three JavaScript。地图组件加载失败保留 SVG，三维失败保留二维点位与表格；主程序导入失败显示可操作重试。检查并修正了地图成功加载后遗留的临时概览及加载中文字。

## 使用新版

本次验证使用临时后端和现有服务的只读访问，**没有停止或迁移正在运行的 8000 旧后端**。代码更新并不自动改变其进程内行为。

请按 [多人部署的升级步骤](team-deployment.md#从-json-账号存储升级) 停旧服务、备份两库与配置、安装锁定依赖并启动新版；禁止旧、新存储实现混跑。升级后的账号库必须加入备份，不能只复制旧 access.json。业务库与账号库的完整恢复点需要停写，不声称两个独立在线 backup 构成原子快照。

模型指标输入格式与同场景验收要求见 [模型与现场验收](model-and-scene-acceptance.md)。下一次能提高真实应用评分的证据，应是同一街区资料、独立人工真值和目标负载/长稳实测结果；本次代码回归不能替代这三项。
